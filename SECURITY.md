# Безопасность

## Как сообщить об уязвимости

Откройте приватное сообщение через вкладку **Security → Report a vulnerability** этого репозитория на GitHub
(Private vulnerability reporting). Не публикуйте детали в открытых issue. Токены и содержимое чужих календарей
в сообщение не вкладывайте.

## Модель угроз

Календарь — статический сайт на GitHub Pages без сервера. Данные лежат в браузере (`localStorage`, IndexedDB)
и, при включённой синхронизации, в GitHub Gist.

- **Токен Gist** хранится в `localStorage` открытым текстом и даёт доступ ко всем Gist аккаунта. Поэтому есть режим
  «только просмотр» (один Gist ID, без токена); токены получают только редакторы, у каждого свой.
- **Origin `*.github.io` общий** для всех Pages-сайтов аккаунта: чужой сайт на том же origin прочитал бы `localStorage`.
- **Секретный Gist доступен по ссылке** — личные данные в события не вносятся.
- **Встраивание в `<iframe>`**: заголовков на Pages нет, защита — `js/guard.js`.
- **Данные извне** (`localStorage`, Gist) проходят `normalizeRecords()`/`validateEvent()`; текст в DOM — через `escapeHtml()`.

Подробности — в разделе «Безопасность» файла `README.md`.
