# calendar_u

Персональный календарь — статическое веб-приложение без бэкенда, сборки и зависимостей.

## Возможности

- **Три вида**: день, неделя, месяц; красная линия «сейчас» в сегодняшней колонке
- **События**: название, дата, время, цвет (5 вариантов), категория (6 значений), место, описание, вложения (до 10 файлов по 5 МБ)
- **Редактирование**: клик по событию в сетке или по карточке в панели дня открывает его для редактирования
- **Повторяющиеся события**: каждый день / неделю (с выбором дней) / месяц / год, интервал, дата окончания; правка и удаление «только это» или «вся серия»
- **Мышью по сетке**: потянуть по пустому месту — создать событие; потянуть блок — перенести (в том числе на другой день); потянуть нижний край — изменить длительность; в месяце — перетащить событие в другую ячейку; двойной клик — событие на час. На телефоне: долгое нажатие на пустом месте
- **Поиск** по названию и месту: фильтрует все виды и показывает список совпадений по всем датам
- **Фильтр по категориям**: выпадающий список в шапке
- **Хранение**: `localStorage` (события, настройки) и IndexedDB (вложения) — работает офлайн
- **Экспорт**: JSON
- **Синхронизация**: через GitHub Gist, слияние по id и времени изменения
- **Настройки**: тема, первый день недели, выходные, формат времени, масштаб сетки
- **Адаптивность**: десктоп, планшет, телефон (в т. ч. ландшафт). Кнопки настроек, синхронизации, Gist и экспорта собраны в меню «⋮»; события месяца — цветные точки; неделя скроллится горизонтально с приклеенной колонкой часов
- **Темы**: системная, светлая, тёмная, сепия, океан, лесная
- **Безопасность**: защита от XSS, prototype pollution, валидация ввода

## Запуск

Откройте `index.html` в браузере — сервер не нужен (скрипты классические, не ES-модули, поэтому работает и по `file://`).

Для разработки можно поднять любой статический сервер:

```bash
python -m http.server 8000
```

## Настройки

Кнопка с шестерёнкой в шапке:

- **Тема оформления**: системная, светлая, тёмная, сепия, океан, лесная
- **Первый день недели**: понедельник, воскресенье или суббота
- **Выходные**: суббота и воскресенье, только воскресенье, суббота и понедельник
- **Формат времени**: 24-часовой или 12-часовой (AM/PM)
- **Масштаб сетки**: компактный (40 px/час), обычный (56), крупный (80)

Настройки сохраняются в `localStorage` и применяются сразу.

## Время событий

Событие отображается ровно в том времени, которое указал пользователь, независимо от часового пояса устройства:

- в хранилище, Gist и экспорте время пишется как локальный ISO без пояса (`2026-10-07T10:00:00`);
- при чтении любой суффикс пояса (`Z`, `+03:00`) отбрасывается — берётся «настенное» время из строки;
- многодневные и заканчивающиеся в полночь события обрезаются по границам суток и не «протекают» на соседние дни.

## Повторяющиеся события

Серия хранится одной записью; вхождения вычисляются на лету. При правке или удалении вхождения спрашивается область: **только это событие** (оно выпадает из серии и становится отдельным) или **вся серия** (при переносе вхождения сдвигается вся серия). Для месячных повторов 29–31-е числа пропускают короткие месяцы.

## Вложения

Файлы хранятся в IndexedDB браузера (лимит — сотни МБ, а не ~5 МБ у `localStorage`), в событии — только имя, размер и тип. Лимит одного файла — 5 МБ. Клик по имени файла в панели дня скачивает его. Если подключён Gist, файлы выгружаются в него как `att-<id>.json` и подтягиваются на другие устройства. Старые вложения из `localStorage` переносятся в IndexedDB автоматически.

Если Gist отклонит большой файл, вложение остаётся только на этом устройстве, а в уведомлении появится предупреждение.

## Синхронизация через GitHub Gist

События синхронизируются между устройствами без бэкенда.

### Настройка

1. Создайте Gist на [gist.github.com](https://gist.github.com) (любой файл, например `calendar-events.json`).
2. Скопируйте Gist ID из URL — строку после последнего `/`:
   ```
   https://gist.github.com/username/a1b2c3d4e5f6...
                            ^^^^^^^^^^^^^^^^^^^^
   ```
3. Создайте Personal Access Token с правом `gist` на [github.com/settings/tokens](https://github.com/settings/tokens).
4. В меню «⋮» нажмите **Gist**, вставьте Gist ID и токен, сохраните.

### Как это работает

- Токен и Gist ID хранятся только в `localStorage` браузера.
- Синхронизация — слияние, а не перезапись: при открытии и через 2 секунды после каждого изменения приложение скачивает Gist, объединяет записи по `id` и времени изменения (`updatedAt`) и записывает результат обратно. Правки с разных устройств не затирают друг друга.
- Побеждает запись с более поздним `updatedAt`. Удаление фиксируется «надгробием» (хранится 90 дней), поэтому удалённое событие не возвращается с другого устройства.
- Кнопка **Синхр.** запускает синхронизацию вручную и показывает ошибки.
- Кнопка **Gist** зелёная (а на кнопке «⋮» горит зелёная точка), когда синхронизация настроена.
- Слияние опирается на системное время устройств — следите, чтобы оно было верным.

### Безопасность

- Токену нужен только scope `gist`.
- Не используйте один токен для нескольких людей — у каждого свой Gist и токен.
- Для приватности делайте Gist секретным (Secret Gist).

## Структура данных

```json
[
  {
    "id": "ev...",
    "title": "Название события",
    "start": "2026-10-07T10:00:00",
    "end": "2026-10-07T11:00:00",
    "location": "Место",
    "description": "Описание",
    "category": "purple",
    "eventCategory": "Конкурс в Москве",
    "attachedFiles": [{ "id": "at...", "name": "file.pdf", "size": 12345, "type": "application/pdf" }],
    "repeat": { "freq": "weekly", "interval": 1, "byDay": [1, 3], "until": "2026-12-31" },
    "exdates": ["2026-10-14"],
    "updatedAt": 1791650000000
  },
  { "id": "ev...", "deleted": true, "updatedAt": 1791650000000 }
]
```

- `category` — цвет: `purple`, `amber`, `pink`, `lavender`, `peach`.
- `eventCategory` — категория: `Конкурс в Москве`, `Выездной конкурс`, `Внутреннее мероприятие`, `Выездное мероприятие`, `Постановка`, `Прочее`.
- `start`/`end` — локальное время без пояса. Для серии это первое вхождение.
- `repeat` — `null` или `{freq: daily|weekly|monthly|yearly, interval, byDay, until}`; `exdates` — даты, исключённые из серии.
- `updatedAt` — время последнего изменения (мс), по нему идёт слияние с Gist. Запись с `deleted: true` — «надгробие» (есть в Gist, но не в экспорте).
- `attachedFiles` — только метаданные; сами файлы в IndexedDB.

## Безопасность

- **XSS**: весь пользовательский ввод экранируется при выводе в DOM
- **Prototype pollution**: объекты очищаются от ключей `__proto__`, `constructor`, `prototype`
- **Валидация**: все записи из `localStorage` и Gist проходят `validateEvent()` — поля ограничены по длине, категории проверяются по белому списку, повторения и вложения — по формату; id очищается от спецсимволов
- **Вложения**: скачиваются как Blob, тип проверяется по маске MIME, файлы не открываются в браузере
- **Ссылки**: внешние ссылки открываются с `rel="noopener noreferrer"`

## Технологии

- Чистые HTML/CSS/JavaScript, без фреймворков и сборки
- GitHub Gist API для синхронизации
- `localStorage` (события, настройки) и IndexedDB (вложения)
