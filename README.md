# calendar_u

Персональный календарь — статическое веб-приложение без бэкенда, сборки и зависимостей.

## Возможности

- **Четыре вида**: день, неделя, месяц и список; красная линия «сейчас» в сегодняшней колонке. «Список» — повестка на 30 дней от выбранной даты: только дни с событиями или праздниками, стрелки листают по 30 дней
- **Праздники РФ**: нерабочие праздники подсвечиваются как выходные и подписаны (в месяце — в ячейке, в других видах — во всплывающей подсказке и заголовке дня). Учтены переносы выходных (ст. 112 ТК РФ и постановления на 2026–2027 годы); отключается в настройках
- **Отмена удаления**: после удаления события, вхождения или серии на 7 секунд появляется плашка «Отменить»
- **События**: название, дата, время, цвет (5 вариантов), категория (6 значений), место, описание, вложения (до 10 файлов по 5 МБ)
- **Выездной конкурс**: при выборе этой категории под ней появляется кнопка «Подробности» — форма из 25 пунктов (положение, заявка, репертуар, контакты, ж/д, трансфер, питание, орг взнос, открытие/закрытие, проживание, фонограмма, свет, дедлайн заявки, аванс, проба сцены, место и размер сцены и др.). На телефоне форма открывается на весь экран с кнопкой «Сохранить» внизу. Подробности сохраняются вместе с событием
- **Редактирование**: клик по событию в сетке или по карточке в панели дня открывает его для редактирования
- **Повторяющиеся события**: каждый день / неделю (с выбором дней) / месяц / год, интервал, дата окончания; правка и удаление «только это» или «вся серия»
- **Мышью по сетке**: потянуть по пустому месту — создать событие; потянуть блок — перенести (в том числе на другой день); потянуть нижний край — изменить длительность; в месяце — перетащить событие в другую ячейку; двойной клик — событие на час. На телефоне: долгое нажатие на пустом месте
- **Поиск** по названию и месту: фильтрует все виды и показывает список совпадений по всем датам
- **Фильтр по категориям**: выпадающий список в шапке
- **Хранение**: `localStorage` (события, настройки) и IndexedDB (вложения) — работает офлайн
- **Приложение на телефоне (PWA)**: устанавливается на домашний экран Android и iOS, запускается без адресной строки и открывается без сети (см. «Установка на телефон»)
- **Экспорт**: JSON
- **Синхронизация**: через GitHub Gist, слияние по id и времени изменения; при открытии, при возврате в приложение и после каждой правки
- **Настройки**: тема, первый день недели, выходные, формат времени, масштаб сетки, праздники РФ
- **Адаптивность**: десктоп, планшет, телефон (в т. ч. ландшафт). Кнопки настроек, синхронизации, Gist и экспорта собраны в меню «⋮»; события месяца — цветные точки; неделя скроллится горизонтально с приклеенной колонкой часов
- **Темы**: системная, светлая, тёмная, сепия, океан, лесная
- **Безопасность**: защита от XSS, prototype pollution, валидация ввода

## Запуск

Откройте `index.html` в браузере — сервер не нужен (скрипты классические, не ES-модули, поэтому работает и по `file://`).

Для разработки можно поднять любой статический сервер:

```bash
python -m http.server 8000
```

## Установка на телефон (PWA)

Календарь можно поставить как приложение: иконка «Ю» на домашнем экране, запуск на весь экран, работа без сети. Для этого страница должна быть открыта по `https://` (GitHub Pages подходит); по `file://` установка недоступна.

### Android (Chrome)

1. Откройте адрес календаря в Chrome.
2. Нажмите «⋮» в правом верхнем углу → **Установить приложение** (в некоторых версиях — **Добавить на главный экран** → **Установить**).
3. Подтвердите. Иконка «Ю» появится на домашнем экране и в списке приложений.

### iPhone и iPad (Safari)

1. Откройте адрес календаря именно в **Safari** (в iOS 16.4+ подойдут и другие браузеры через меню «Поделиться», но Safari надёжнее).
2. Нажмите кнопку **Поделиться** (квадрат со стрелкой вверх) → прокрутите список → **На экран «Домой»**.
3. Оставьте название «Календарь» и нажмите **Добавить**.

### После установки

- Установленное приложение хранит данные **отдельно от браузера** (особенно на iOS): события из обычной вкладки в нём не появятся сами. Откройте «⋮» → **Gist** и введите Gist ID (редактору — и токен): календарь подтянется из Gist. Без Gist события в приложении и во вкладке не связаны.
- Календарь обновляется из Gist при запуске, при возврате в приложение (не чаще раза в 30 секунд) и после каждой правки. Правка, сделанная без сети, уйдёт в Gist, когда сеть вернётся.
- Новая версия подхватывается при следующем запуске с сетью: если интерфейс не обновился, закройте приложение полностью и откройте снова.
- Удалить — как любое приложение: долгое нажатие на иконке → **Удалить**. Данные приложения при этом стираются; события, выгруженные в Gist, остаются.

## Настройки

Кнопка с шестерёнкой в шапке:

- **Тема оформления**: системная, светлая, тёмная, сепия, океан, лесная
- **Первый день недели**: понедельник, воскресенье или суббота
- **Выходные**: суббота и воскресенье, только воскресенье, суббота и понедельник
- **Формат времени**: 24-часовой или 12-часовой (AM/PM)
- **Масштаб сетки**: компактный (40 px/час), обычный (56), крупный (80)
- **Праздники РФ**: показывать и подсвечивать или скрыть

Настройки сохраняются в `localStorage` и применяются сразу.

## Время событий

Событие отображается ровно в том времени, которое указал пользователь, независимо от часового пояса устройства:

- в хранилище, Gist и экспорте время пишется как локальный ISO без пояса (`2026-10-07T10:00:00`);
- при чтении любой суффикс пояса (`Z`, `+03:00`) отбрасывается — берётся «настенное» время из строки;
- многодневные и заканчивающиеся в полночь события обрезаются по границам суток и не «протекают» на соседние дни.

## Повторяющиеся события

Серия хранится одной записью; вхождения вычисляются на лету. При правке или удалении вхождения спрашивается область: **только это событие** (оно выпадает из серии и становится отдельным) или **вся серия** (при переносе вхождения сдвигается вся серия). Для месячных повторов 29–31-е числа пропускают короткие месяцы.

## Вложения

Файлы хранятся в IndexedDB браузера (лимит — сотни МБ, а не ~5 МБ у `localStorage`), в событии — только имя, размер и тип. Лимит одного файла — 5 МБ. Клик по имени файла в панели дня скачивает его. Если подключён Gist, файлы выгружаются в него как `att-<id>.json` и подтягиваются на другие устройства. Старые вложения из `localStorage` переносятся в IndexedDB автоматически.

Если Gist отклонит большой файл, вложение остаётся только на этом устройстве, а в уведомлении появится предупреждение.

## Синхронизация через GitHub Gist

События синхронизируются между устройствами без бэкенда.

Есть два режима:

- **Редактор** (Gist ID + токен): читает и пишет, изменения уходят всем. Для владельца и тех, кому доверено править календарь.
- **Только просмотр** (один Gist ID, без токена): календарь только читается и обновляется при открытии, при возврате в приложение и по кнопке «Синхр.». Править нельзя (кнопки добавления и правки показывают подсказку). Токен таким пользователям **не нужен и не выдаётся**.

### Настройка (владелец)

1. Создайте **секретный** Gist на [gist.github.com](https://gist.github.com) (любой файл, например `calendar-events.json`).
2. Скопируйте Gist ID из URL — строку после последнего `/`:
   ```
   https://gist.github.com/username/a1b2c3d4e5f6...
                            ^^^^^^^^^^^^^^^^^^^^
   ```
3. Для редакторов создайте классический Personal Access Token на [github.com/settings/tokens](https://github.com/settings/tokens): единственное право `gist`, срок жизни 90 дней, название вида «календарь — Имя» (**отдельный токен на каждого редактора**, чтобы отзывать по одному).
4. В меню «⋮» нажмите **Gist**: редактору — Gist ID и токен, остальным — только Gist ID. Токен после сохранения в поле не показывается; пустое поле при повторном сохранении оставляет прежний токен. Кнопка **Отключить Gist** стирает ID и токен с этого устройства (события остаются).

### Как это работает

- Токен и Gist ID хранятся только в `localStorage` браузера (в открытом виде — как у любого сайта без сервера). Токен уходит только на `api.github.com`; в режиме просмотра запросы идут без токена.
- Синхронизация — слияние, а не перезапись: при открытии, при возврате в приложение (не чаще раза в 30 секунд), при появлении сети и через 2 секунды после каждого изменения приложение скачивает Gist, объединяет записи по `id` и времени изменения (`updatedAt`) и записывает результат обратно. Правки с разных устройств не затирают друг друга.
- Слияние идёт **по полям**: у события есть группы полей (название, время, место, описание, цвет, категория с подробностями, вложения), и у каждой своя метка времени. Если на одном устройстве поменяли название, а на другом — место, сохранятся обе правки. Время начала, конца и повторение — одна группа: их нельзя взять от разных устройств. Если одно и то же поле поменяли на двух устройствах, побеждает более поздняя правка.
- Событие против удаления: побеждает более поздняя метка. Удаление фиксируется «надгробием» (хранится 90 дней), поэтому удалённое событие не возвращается с другого устройства.
- Кнопка **Синхр.** запускает синхронизацию вручную и показывает ошибки.
- Кнопка **Gist** зелёная (а на кнопке «⋮» горит зелёная точка), когда синхронизация настроена.
- Слияние опирается на системное время устройств — следите, чтобы оно было верным.
- Если токен истёк или отозван, приложение покажет «Токен истек - синхронизация не работает. Свяжитесь с разработчиком.», на кнопке «⋮» загорится красная точка, а автосинхронизация остановится. Календарь продолжит работать локально; после ввода нового токена накопленные правки сольются с Gist.

### Безопасность Gist

- Токен с `gist` даёт доступ ко **всем** Gist аккаунта (чтение, правку, удаление). Поэтому токены — только редакторам, остальным — режим просмотра; хранить токен в мессенджерах и почте нельзя, передавать лично. Лучше всего завести отдельный GitHub-аккаунт только под календарь; в любом случае на аккаунте включите 2FA и уберите из Gist всё личное.
- Токен утёк или человек ушёл из коллектива — отзовите его на [github.com/settings/tokens](https://github.com/settings/tokens) и выдайте новый.
- Секретный Gist — это «доступен по ссылке», а не приватный: любой, кто знает ID, прочитает календарь. Не вносите в события телефоны, адреса и данные несовершеннолетних; в подробностях выездных конкурсов — только рабочие сведения.
- Токен истекает (90 дней): запишите дату и продлите заранее.
- **Восстановление:** у Gist есть история ревизий. Откройте Gist на gist.github.com → «Revisions» → нужная версия → «Raw» и вставьте содержимое `calendar-events.json` обратно в Gist (кнопка «Edit»). Остальные устройства подтянут его при следующей синхронизации. Перед крупными правками полезно сделать «Экспорт» в JSON.
- Пока на этом `github.io` лежат другие сайты, они могли бы читать `localStorage` календаря (общий origin). Держите на аккаунте только календарь или вынесите его в организацию — у неё будет свой `org.github.io`.

## Для коллектива

1. Откройте адрес календаря. Меню «⋮» → **Gist** → введите Gist ID, который дал владелец → «Сохранить». Токен не нужен: это режим просмотра.
2. Чтобы календарь обновился, нажмите **Синхр.** (он также обновляется при каждом открытии).
3. Если нужно править календарь, обратитесь к владельцу: он выдаст токен редактора.
4. Не вносите в события личные данные (телефоны, адреса, данные детей).
5. Увидели «Токен истек…» — сообщите владельцу.

## Структура данных

```json
[
  {
    "id": "ev...",
    "title": "Название события",
    "start": "2026-10-07T10:00:00",
    "end": "2026-10-07T11:00:00",
    "location": "Место",
    "description": "Описание",
    "category": "purple",
    "eventCategory": "Конкурс в Москве",
    "details": {},
    "attachedFiles": [{ "id": "at...", "name": "file.pdf", "size": 12345, "type": "application/pdf" }],
    "repeat": { "freq": "weekly", "interval": 1, "byDay": [1, 3], "until": "2026-12-31" },
    "exdates": ["2026-10-14"],
    "fieldTimes": { "title": 1791650000000, "location": 1791640000000 },
    "updatedAt": 1791650000000
  },
  { "id": "ev...", "deleted": true, "updatedAt": 1791650000000 }
]
```

- `category` — цвет: `purple`, `amber`, `pink`, `lavender`, `peach`.
- `eventCategory` — категория: `Конкурс в Москве`, `Выездной конкурс`, `Внутреннее мероприятие`, `Выездное мероприятие`, `Постановка`, `Прочее`.
- `details` — только у `Выездной конкурс`: объект `{ключ: строка}` (ключи — `TRIP_FIELDS` в `js/config.js`, например `contacts`, `trainOut`, `orgFee`); пустые значения не хранятся, при другой категории поле сбрасывается в `{}`.
- `start`/`end` — локальное время без пояса. Для серии это первое вхождение.
- `repeat` — `null` или `{freq: daily|weekly|monthly|yearly, interval, byDay, until}`; `exdates` — даты, исключённые из серии.
- `updatedAt` — время последнего изменения (мс). `fieldTimes` — необязательно: время последней правки каждой группы полей (`title`, `when`, `location`, `description`, `color`, `kind`, `files`); у записи без него все группы считаются изменёнными в `updatedAt`. По ним идёт слияние с Gist. Запись с `deleted: true` — «надгробие» (есть в Gist, но не в экспорте).
- `attachedFiles` — только метаданные; сами файлы в IndexedDB.

## Безопасность

- **XSS**: весь пользовательский ввод экранируется при выводе в DOM (`escapeHtml`/`textContent`), inline-скриптов и обработчиков нет
- **Prototype pollution**: объекты очищаются от ключей `__proto__`, `constructor`, `prototype`
- **Валидация**: все записи из `localStorage` и Gist проходят `validateEvent()` — поля ограничены по длине, категории проверяются по белому списку, повторения и вложения — по формату; id очищается от спецсимволов
- **CSP**: `<meta http-equiv="Content-Security-Policy">` в `index.html` — только свои скрипты (без inline), стили — свои файлы плюс `style=""` в атрибутах, картинки только свои, запросы только к `api.github.com` и `gist.githubusercontent.com`; `referrer` отключён
- **Встраивание (clickjacking)**: GitHub Pages не отдаёт `X-Frame-Options`/`frame-ancestors`, поэтому `js/guard.js` прячет интерфейс и не запускает приложение, если страница открыта внутри чужого `<iframe>`
- **Gist**: ID проверяется как hex (он идёт в путь запроса), токен — по формату; `raw_url` принимается только с `gist.githubusercontent.com`; размер файлов и base64 из Gist проверяются до разбора
- **Лимиты**: не более 5000 событий и 5000 «надгробий», глубина JSON ограничена; метки времени (`updatedAt`, `fieldTimes`) — конечные числа не дальше года вперёд, иначе отбрасываются
- **Вложения**: скачиваются как Blob, тип проверяется по маске MIME, имя файла очищается от путей и служебных символов, файлы не открываются в браузере
- **Ссылки**: внешних ссылок в приложении нет
- **Сообщить об уязвимости**: см. `SECURITY.md`
