# CLAUDE.md — инструкции для разработки календаря

Этот файл Claude Code читает автоматически в начале каждой сессии. Правила ниже обязательны для любых изменений.
Если вносишь изменение, которое делает правило устаревшим, — обнови правило в этом же коммите.

## Как работать над проектом

1. **Перед правкой** прочитай этот файл и затронутые модули целиком. Структура и порядок скриптов — в разделе «Структура проекта».
2. **Язык**: код — английские идентификаторы, комментарии, UI-тексты и документация — по-русски.
3. **Без сборки и зависимостей**: чистые HTML/CSS/JS, классические скрипты (не ES-модули), чтобы `index.html` открывался по `file://` и работал на GitHub Pages. Новые npm-пакеты, сборщики и CDN-библиотеки не добавлять без явной просьбы.
4. **Один источник правды**: константы — `js/config.js`, пересчёт дат — `js/utils.js`/`js/recurrence.js`, любое изменение данных — через `js/events.js`. Не дублировать логику в `ui.js`/`render.js`.
5. **Проверка**: после правок `node --check js/*.js`, затем запусти `python -m http.server 8000` и проверь страницу в браузере (панель Claude по `file://` показывает статический снимок без JS — нужен http). Консоль должна быть чистой. Проверь десктоп и мобильную ширину (375 px), для UI-правок — тёмную и светлую темы.
6. **Документация**: после изменения поведения, структуры или правил обнови `README.md` (для пользователя) и этот файл (для разработки). Таблицы «Структура» и «Основные функции» должны соответствовать коду.
7. **Git**: коммитить и пушить только по просьбе пользователя. Сообщения коммитов — кратко, по сути изменения.
8. **Объём**: не добавлять фич и рефакторингов сверх просьбы; найденные «заодно» проблемы — упомянуть в ответе, а не чинить молча, если это не мелочь в тех же строках.
9. **Данные пользователя** (`localStorage`, IndexedDB, Gist) нельзя ломать: меняешь формат — пиши миграцию и читай старый формат (как `migrateLegacyAttachments`, события без `updatedAt`).

## Правила кода

1. **Темы** — атрибут `data-theme` на `<html>` (`dark`, `sepia`, `ocean`, `forest`; «светлая» и «системная» — по умолчанию). Все переменные (`--bg`, `--bg-soft`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-muted`, `--weekend-bg`, `--overlay`, `--c-*`) определяются в `css/themes.css` для каждой темы. Цвета вне `themes.css` не хардкодить — только переменные (`--glow`, `--glow-soft`, `--line` — производные от `--c-purple`).

2. **Скролл** — `body { overflow: hidden }`, глобального скролла нет. Сетка дня/недели — единый скролл-контейнер `.time-grid-wrapper`: заголовок `.time-grid-header` приклеен сверху, колонка часов — слева, у заголовка и тела общий `min-width`. Панель дня скроллится сама (`max-height: 42dvh`).

3. **Модальные окна** — закрытие по клику вне окна только через `mousedown`, не `click`. Escape закрывает все открытые окна (`closeOverlay`). Диалог области действия `#scopeModal` при закрытии возвращает `null` (отмена).

4. **События в сетке** — позиции в процентах с зазором: `left = col.x * (100 / col.total) + 1.5 %`, `width = 100 / col.total - 3 %`. Раскладка — `layoutEvents()` (кластеры пересечений).

5. **Высота часа** — только `settings.hourHeight`, пробрасывается в CSS как `--hour-height` на `.time-grid-wrapper`. Не задавать высоту `.hour-line`/`.hour-label` в медиазапросах — события «уедут» от своего времени (на мобильных так уже было).

6. **Иконки** — только inline SVG с `currentColor` (в HTML или в `ICONS`, `js/config.js`). Юникод-символы вместо иконок не использовать.

7. **Select** — оборачивать в `<div class="select-wrapper">`, стрелка рисуется на обёртке.

8. **Время событий** — «настенное» время ровно как ввёл пользователь, без перевода между поясами: создание — `parseLocalIso(date + "T" + time)`; хранение — локальный ISO без пояса (`fmtLocalIso`); чтение — `parseLocalIso` берёт компоненты из строки и отбрасывает суффикс пояса. `new Date(string)` для событий не использовать. Отображение по дню — `eventSegment()` (обрезка по суткам).

9. **Данные извне** (`localStorage`, Gist, импорт) — только через `normalizeRecords()` → `validateEvent()`. Пользовательский текст в DOM — только через `escapeHtml()` или `textContent`. Вложения: `dataUrl` не рендерить как ссылку/`src`; скачивать через Blob, тип проверять `safeMime()`.

10. **Повторяющиеся события** — серия хранится одной записью (мастер: `start`/`end` первого вхождения + `repeat` + `exdates`); вхождения разворачиваются на лету в экземпляры с id `<id>@<YYYY-MM-DD>` (`recurrence.js`). Символ `@` зарезервирован (`cleanId` его вырезает). В DOM и в `data-id` всегда id экземпляра; искать — `findEventById()`. Изменение/удаление экземпляра — только через `applyEventChange()`/`deleteEvent()` (они спрашивают «это событие / вся серия»).

11. **Синхронизация с Gist** — слияние по `id` и `updatedAt` (`mergeRecords`): побеждает большее `updatedAt`, при равенстве локальная запись, удаление сильнее правки. Удаление = «надгробие» `{id, deleted:true, updatedAt}` (хранится 90 дней). Любое изменение события обязано обновлять `updatedAt` (`touch()` в `events.js`) — иначе правка потеряется при слиянии. Не писать в `state.events` напрямую из UI.

12. **Вложения** — файлы лежат в IndexedDB (`attachments.js`), в событии только `{id, name, size, type}`. Лимит файла `MAX_ATTACH_BYTES` (5 МБ). В Gist каждый файл — `att-<id>.json` (base64), выгружается отдельным запросом. Сборщик мусора `gcAttachments()` удаляет файлы без ссылок; пока идёт запись (`attSaving > 0`) он не работает.

13. **Перетаскивание** (`drag.js`) — Pointer Events; мышь/перо: создать (тянуть по колонке), перенести, растянуть, перенос в ячейку месяца. Тач: только долгое нажатие для создания (не мешать скроллу). После drag клик гасится через `clickSuppressed()` — новые click-обработчики в сетке должны его проверять.

14. **Шапка** — действия (настройки, синхронизация, Gist, экспорт) на любой ширине живут в выпадающем меню кнопки «⋮» (`.header-actions` — popover, стили в `base.css`). Новые кнопки действий добавлять внутрь `#headerActions`, отдельных иконок в шапке не делать.

## Проверки перед коммитом

- [ ] `node --check js/*.js` без ошибок, консоль браузера чистая
- [ ] Все темы (auto/light/dark/sepia/ocean/forest) выглядят корректно
- [ ] Нет скролла страницы; модалки не закрываются при отпускании мыши за их пределами
- [ ] Событие стоит напротив своих часов на десктопе **и** на мобильном; 10:00–11:00 остаётся 10:00–11:00 в любом часовом поясе
- [ ] Повтор: вхождения на нужных днях; правка/удаление «только это» и «вся серия» работают
- [ ] Перетаскивание: создание, перенос между днями, изменение длительности
- [ ] Поиск и фильтр категорий работают во всех видах и в панели дня
- [ ] Слияние: правка с двух устройств не затирает друг друга, удаление не «воскресает»
- [ ] Вложение сохраняется, скачивается, переживает перезагрузку
- [ ] Адаптивность: 320, 375, 768, 1024, 1440 px и ландшафт телефона; меню «⋮» открывается и закрывается

## Темы оформления

| Тема | `data-theme` | Описание |
|------|--------------|----------|
| Системная | — (нет атрибута) | Светлая/тёмная по `prefers-color-scheme` |
| Светлая | `light` | Светлая палитра |
| Тёмная | `dark` | Тёмная палитра |
| Сепия | `sepia` | Тёплая бежевая гамма |
| Океан | `ocean` | Сине-бирюзовая гамма |
| Лесная | `forest` | Зелёная гамма |

## Структура проекта

```
index.html           разметка, подключение css/js
CLAUDE.md            этот файл
README.md            описание для пользователя
assets/favicon.svg
css/
  themes.css         токены и темы
  base.css           сброс, шапка, кнопки, поиск, фильтр, меню действий
  calendar.css       месяц, неделя/день, панель дня, перетаскивание
  modal.css          модалки, формы, повторение, тост
  responsive.css     все медиазапросы (подключается последним)
js/                  порядок = порядок <script> в index.html
  config.js          константы, state, DEFAULT_SETTINGS, ICONS
  utils.js           даты, escapeHtml, validateEvent, normalizeRecords, mergeRecords, eventsForDay, layoutEvents
  recurrence.js      повторения: occursOn, occurrencesIn, findEventById, repeatLabel
  settings.js        loadSettings/saveSettings/applyTheme
  attachments.js     IndexedDB: вложения, миграция, скачивание, gc
  storage.js         saveEvents/loadStoredEvents/exportEvents
  gist.js            gistSync (слияние), gistFetchAttachment, scheduleGistSync
  events.js          createEvent/applyEventChange/deleteEvent (updatedAt, надгробия, область действия)
  render.js          render*, renderPanel, updateNowLines
  drag.js            создание/перенос/растягивание мышью, долгое нажатие на таче
  ui.js              модалки, повторение, вложения, поиск, фильтр, меню, навигация, настройки
  main.js            инициализация
```

Куда класть код: стили — в тематический файл, медиазапросы — в `responsive.css`; чистые функции дат/данных — `utils.js`/`recurrence.js`; изменение данных — `events.js`; рисование DOM — `render.js`; обработчики — `ui.js`/`drag.js`.

## Примечания

- Два «категорийных» поля: `category` — цвет (5 значений), `eventCategory` — текстовая категория (`EVENT_CATEGORIES` в `config.js`, используется в фильтре и модалке).
- Формат записи события: `id, title, start, end, location, description, category, eventCategory, attachedFiles[{id,name,size,type}], repeat{freq,interval,byDay,until}|null, exdates[], updatedAt`.
- Слияние опирается на часы устройств: сильно расходящееся системное время даст «неправильного победителя».
- Разработка: `python -m http.server 8000`.
