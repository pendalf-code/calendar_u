# CLAUDE.md — инструкции для разработки календаря

Этот файл Claude Code читает автоматически в начале каждой сессии. Правила ниже обязательны для любых изменений.
Если вносишь изменение, которое делает правило устаревшим, — обнови правило в этом же коммите.

## Как работать над проектом

1. **Перед правкой** прочитай этот файл и затронутые модули целиком. Структура и порядок скриптов — в разделе «Структура проекта».
2. **Язык**: код — английские идентификаторы, комментарии, UI-тексты и документация — по-русски.
3. **Без сборки и зависимостей**: чистые HTML/CSS/JS, классические скрипты (не ES-модули), чтобы `index.html` открывался по `file://` и работал на GitHub Pages. Новые npm-пакеты, сборщики и CDN-библиотеки не добавлять без явной просьбы.
4. **Один источник правды**: константы — `js/config.js`, пересчёт дат — `js/utils.js`/`js/recurrence.js`, любое изменение данных — через `js/events.js`. Не дублировать логику в `ui.js`/`render.js`.
5. **Проверка**: после правок `node --check js/*.js` и `node --test "tests/*.test.js"`, затем запусти `python -m http.server 8000` и проверь страницу в браузере (панель Claude по `file://` показывает статический снимок без JS — нужен http). Консоль должна быть чистой. Проверь десктоп и мобильную ширину (375 px), для UI-правок — тёмную и светлую темы.
6. **Документация**: после изменения поведения, структуры или правил обнови `README.md` (для пользователя) и этот файл (для разработки). Таблицы «Структура» и «Основные функции» должны соответствовать коду.
7. **Git**: коммитить и пушить только по просьбе пользователя. Сообщения коммитов — кратко, по сути изменения.
8. **Объём**: не добавлять фич и рефакторингов сверх просьбы; найденные «заодно» проблемы — упомянуть в ответе, а не чинить молча, если это не мелочь в тех же строках.
9. **Кэш GitHub Pages**: ресурсы в `index.html` подключены с `?v=N`. При каждом изменении css/js поднимай `N` во всех ссылках (иначе пользователи до 10 минут видят старые файлы вперемешку с новой разметкой).
10. **Данные пользователя** (`localStorage`, IndexedDB, Gist) нельзя ломать: меняешь формат — пиши миграцию и читай старый формат (как `migrateLegacyAttachments`, события без `updatedAt`).

## Правила кода

1. **Темы** — атрибут `data-theme` на `<html>` (`dark`, `sepia`, `ocean`, `forest`; «светлая» и «системная» — по умолчанию). Все переменные (`--bg`, `--bg-soft`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-muted`, `--weekend-accent`, `--weekend-strength`, `--overlay`, `--c-*`; `--weekend-bg` считается от `--surface`, `--weekend-accent` и `--weekend-strength`; акцент выходных берётся из палитры темы, не общий розовый) определяются в `css/themes.css` для каждой темы. Цвета вне `themes.css` не хардкодить — только переменные (`--glow`, `--glow-soft`, `--line` — производные от `--c-purple`; выходные — только через `--weekend-accent`/`--weekend-bg`).

2. **Скролл** — `body { overflow: hidden }`, глобального скролла нет. Сетка дня/недели — единый скролл-контейнер `.time-grid-wrapper`: заголовок `.time-grid-header` приклеен сверху, колонка часов — слева, у заголовка и тела общий `min-width`. Панель дня скроллится сама (`max-height: 42dvh`).

3. **Модальные окна** — закрытие по клику вне окна только через `mousedown`, не `click`. Escape закрывает все открытые окна (`closeOverlay`). Диалог области действия `#scopeModal` при закрытии возвращает `null` (отмена).

4. **События в сетке** — позиции в процентах с зазором: `left = col.x * (100 / col.total) + 1.5 %`, `width = 100 / col.total - 3 %`. Раскладка — `layoutEvents()` (кластеры пересечений).

5. **Высота часа** — только `settings.hourHeight`, пробрасывается в CSS как `--hour-height` на `.time-grid-wrapper`. Не задавать высоту `.hour-line`/`.hour-label` в медиазапросах — события «уедут» от своего времени (на мобильных так уже было).

6. **Иконки** — только inline SVG с `currentColor` (в HTML или в `ICONS`, `js/config.js`). Юникод-символы вместо иконок не использовать.

7. **Select** — оборачивать в `<div class="select-wrapper">`: `enhanceSelect()` (`js/select.js`, вызывается в `main.js`) заменяет его кастомным списком, а нативный `<select>` прячет, но оставляет источником `value`/`change`. `select.value = ...` из кода работает как раньше (подпись обновляется сама). Список выносится в `<body>` (`position: fixed`), чтобы не обрезался модалкой. Селекты, добавленные после старта, нужно прогонять через `enhanceSelect()`.

8. **Время событий** — «настенное» время ровно как ввёл пользователь, без перевода между поясами: создание — `parseLocalIso(date + "T" + time)`; хранение — локальный ISO без пояса (`fmtLocalIso`); чтение — `parseLocalIso` берёт компоненты из строки и отбрасывает суффикс пояса. `new Date(string)` для событий не использовать. Отображение по дню — `eventSegment()` (обрезка по суткам).

9. **Данные извне** (`localStorage`, Gist, импорт) — только через `normalizeRecords()` → `validateEvent()`. Пользовательский текст в DOM — только через `escapeHtml()` или `textContent`. Вложения: `dataUrl` не рендерить как ссылку/`src`; скачивать через Blob, тип проверять `safeMime()`, имя — `safeFileName()`. Ответы Gist недоверенные: ограничивать размер (`gistReadFile`), base64 проверять (`base64ToBlob`), `raw_url` — только `GIST_RAW_ORIGIN`; Gist ID/токен — `validGistId`/`validGistToken`. Лимиты — в `config.js` (`MAX_RECORDS`, `MAX_JSON_DEPTH`, …). В `index.html` действует CSP (`script-src 'self'`): inline-скрипты и обработчики `onclick=` запрещены, новый внешний хост — только осознанно, добавив его в `connect-src`.

10. **Повторяющиеся события** — серия хранится одной записью (мастер: `start`/`end` первого вхождения + `repeat` + `exdates`); вхождения разворачиваются на лету в экземпляры с id `<id>@<YYYY-MM-DD>` (`recurrence.js`). Символ `@` зарезервирован (`cleanId` его вырезает). В DOM и в `data-id` всегда id экземпляра; искать — `findEventById()`. Изменение/удаление экземпляра — только через `applyEventChange()`/`deleteEvent()` (они спрашивают «это событие / вся серия»).

11. **Синхронизация с Gist** — слияние по `id` (`mergeRecords`). Событие против события — **по группам полей** (`MERGE_GROUPS` в `config.js`, `mergeEventFields`): у каждой группы своя метка `fieldTimes[группа]`, берётся более поздняя, при равенстве локальная; нет `fieldTimes` (старый формат) — метка группы = `updatedAt`. Событие против «надгробия» `{id, deleted:true, updatedAt}` (хранится 90 дней): побеждает большее `updatedAt`, при равенстве удаление. Любое изменение события обязано обновлять метки через `touch(e, группы)` в `events.js` (только изменившиеся группы; `touch(e)` без групп — «всё событие»: создание, восстановление) — иначе правка потеряется при слиянии. Новое поле события = добавить в группу `MERGE_GROUPS` (или завести новую); `start/end/repeat/exdates` — одна группа, не разрывать. Не писать в `state.events` напрямую из UI.

12. **Вложения** — файлы лежат в IndexedDB (`attachments.js`), в событии только `{id, name, size, type}`. Лимит файла `MAX_ATTACH_BYTES` (5 МБ). В Gist каждый файл — `att-<id>.json` (base64), выгружается отдельным запросом. Сборщик мусора `gcAttachments()` удаляет файлы без ссылок; пока идёт запись (`attSaving > 0`) он не работает. Пока висит плашка «Отменить» (`showUndo`, `UNDO_MS`), счётчик `gcHold > 0` — сборщик мусора не работает, файлы удалённого события ещё нужны. Ответ GitHub `401` (токен истёк) помечает синхронизацию сломанной (`gistAuthBroken`): показывается тост `TOKEN_EXPIRED_MSG`, на «⋮» красная точка, автосинхронизация не повторяется до ручной попытки или ввода нового токена.

13. **Перетаскивание** (`drag.js`) — Pointer Events; мышь/перо: создать (тянуть по колонке), перенести, растянуть, перенос в ячейку месяца. Тач: только долгое нажатие для создания (не мешать скроллу). После drag клик гасится через `clickSuppressed()` — новые click-обработчики в сетке должны его проверять.

14. **Шапка** — действия (настройки, синхронизация, Gist, экспорт) на любой ширине живут в выпадающем меню кнопки «⋮» (`.header-actions` — popover, стили в `base.css`). Новые кнопки действий добавлять внутрь `#headerActions`, отдельных иконок в шапке не делать.

15. **Подробности выездного конкурса** — список пунктов только в `TRIP_FIELDS` (`js/config.js`); форма `#detailsModal` строится из него (`buildDetailsFields`), валидация — `normalizeDetails()` (`utils.js`). Новый пункт = строка в `TRIP_FIELDS`, остальное подхватывается само. Это черновик `tripDetails` в `ui.js`: «Сохранить» в подробностях только обновляет черновик, в событие он попадает при сохранении события; у других категорий `details` всегда `{}`. Окно на телефоне (≤600 px) — на весь экран, кнопки закреплены внизу.

16. **Поля даты/времени** — `input[type=date|time|number]` в `.field` сброшены через `appearance: none` + `min-width: 0` (`modal.css`): iOS Safari иначе игнорирует ширину и центрирует значение. На ≤600 px (`responsive.css`) все поля формы 46 px высотой и 16 px шрифтом (иначе iOS зумит при фокусе); `.field-row` — grid: дата на всю ширину, «Начало»/«Конец» — две колонки.

17. **Удаление с отменой** — `deleteEvent()` не просит подтверждения, а вызывает `showUndo(сообщение, restore)` (`ui.js`): отдельная плашка `#undoBar` (не тост — тост перекрывается сообщениями синхронизации), одна на всё приложение; новое удаление отнимает возможность отменить предыдущее. `restore()` только меняет данные (новый `updatedAt` сильнее «надгробия»), сохранение и перерисовку делает кнопка, затем `closeUndo()` (снимает `gcHold`). Отмена удаления вхождения убирает из `exdates` только свою дату.

18. **Вид «Список»** (`state.view = "agenda"`, `renderAgenda()`) — `AGENDA_DAYS` дней от `state.anchor`, стрелки листают на столько же; панель дня в нём закрыта, карточки те же (`buildEventCard()`), новое событие — кнопка вверху списка. После сохранения события окно не прыгает, если событие внутри окна.

19. **Праздники РФ** — отдельный слой (`holidays.js`): `holidayName(date)` → подпись или `null` (слой выключен `settings.holidays`). Подсветка — класс `weekend` (+ `holiday` в месяце), цвета только через `--weekend-*`. Фиксированные даты — `RU_HOLIDAYS`, переносы по ст. 112 считаются сами (кроме 1–8 января), переносы по постановлениям — `RU_DAYOFF_DECREES` по годам; **раз в год** добавлять новый год из постановления Правительства.

20. **Тесты** (`tests/*.test.js`, запуск `node --test "tests/*.test.js"`) грузят настоящие `config/utils/recurrence/holidays/events.js` через `tests/helpers.js` (скрипты склеиваются в одну функцию, UI-функции — заглушки). Новую чистую логику — с тестом; в тестируемых файлах нет обращений к DOM на верхнем уровне (иначе добавить заглушку в `helpers.js`).

## Примечания

- Два «категорийных» поля: `category` — цвет (5 значений), `eventCategory` — текстовая категория (`EVENT_CATEGORIES` в `config.js`, используется в фильтре и модалке).
- Формат записи события: `id, title, start, end, location, description, category, eventCategory, details{key:string}, attachedFiles[{id,name,size,type}], repeat{freq,interval,byDay,until}|null, exdates[], fieldTimes{группа:мс}?, updatedAt`.
- Слияние опирается на часы устройств: сильно расходящееся системное время даст «неправильного победителя».
- Разработка: `python -m http.server 8000`.
